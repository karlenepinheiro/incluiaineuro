4Inconsistências e Riscos
🔴
4.1 Crítico — PDFGenerator sem branches para PEI / PAEE / PDI
O mesmo loop genérico renderiza os três documentos. PEI com 14 seções de BNCC e PAEE com seções de acessibilidade ficam visualmente idênticos no PDF. Não há identidade visual diferenciada nem validação de completude.
// PDFGenerator.ts L2668
if (isEstudoCasoDocType(docType)) {
  y = renderEstudoCasoPremium(...);  // ← renderer rico, 17 seções canônicas
  addFooterAllPages(doc);
  return doc.output('blob');          // ← return intencional ✓
}

// L2674 — loop genérico para PEI, PAEE, PDI e TODOS os outros
for (const sec of sections) {
  sectionBanner(doc, sec.title, ML, y, maxW);  // ← sem distinção alguma ⚠
  for (const field of sec.fields) {
    // renderiza campo genérico — igual para os três documentos
  }
}
🔴
4.2 Crítico — Print usa HTML do preview, não o PDF
O botão "Imprimir" chama window.print() sobre o DOM do DocumentPrintPreview (HTML/CSS). O botão "Gerar PDF" usa jsPDF. Os dois caminhos produzem documentos visualmente diferentes. O usuário não sabe que está imprimindo um documento diferente do PDF que baixa.
🟠
4.3 Alto — Enriquecimento automático bloqueado para PEI / PAEE / PDI
O useEffect que injeta fichas, laudos e histórico do aluno nos campos do documento tem um return prematuro explícito para qualquer coisa que não seja Estudo de Caso. PEI, PAEE e PDI sempre abrem com seções vazias, mesmo que o aluno já tenha dados completos no banco.
// DocumentBuilder.tsx L393-397
useEffect(() => {
  if (step !== 'editor') return;
  if (type !== DocumentType.ESTUDO_CASO) return;  // ← BLOQUEIO EXPLÍCITO
  if (!selectedStudent?.id) return;

  StudentContextService.buildContext(selectedStudent.id).then(ctx => {
    // injeta fichas, laudos, perfil cognitivo — SÓ para Estudo de Caso
  });
}, [step, selectedStudent?.id, type]);
🟠
4.4 Alto — STANDARD_DOC_FIELDS definido mas nunca usado
Há uma constante com as seções esperadas para PEI, PAEE e PDI, mas ela não é referenciada em nenhum outro lugar do arquivo. Documentos incompletos podem ser salvos como "APROVADOS" sem qualquer aviso.
// DocumentBuilder.tsx L60-66
const STANDARD_DOC_FIELDS: Record<string, string> = {
  PEI:  'Identificação do Aluno, Diagnóstico e CID, ..., Assinaturas',
  PAEE: 'Identificação do Aluno, Demanda e Encaminhamento, ...',
  PDI:  'Identificação, Diagnóstico, Perfil de Aprendizagem, ...',
};
// ↑ NUNCA é referenciado em nenhum outro lugar — validator não existe
🟡
4.5 Médio — PDI pode não gerar código VAL-
VALIDATED_TYPES em documentCodes.ts contém: PEI, PAEE, ESTUDO_CASO, PLANO_ACAO_AEE. O PDI não aparece na lista. Isso significa que PDI gera código REG- (registro) em vez de VAL- (validação). Verificar se isso é intencional.
🟡
4.6 Médio — Normalização de doc_type duplicada e inconsistente
databaseService.ts e documentCodes.ts fazem normalização de strings em direções opostas. Um converte espaço → underscore, o outro faz o inverso. A constante VALIDATED_TYPES aceita os dois formatos como proteção defensiva, mas o código está duplicado e frágil.
🟢
4.7 Baixo — Renderizador morto sem remoção formal
renderEstudoCasoCompactProtocol() está comentado com nota "Sprint 1 removido". O bloco comentado ainda existe no arquivo e polui a leitura.
5Auditoria Pedagógica dos Prompts de IA
PEI

Plano Educacional Individualizado

Foco: O QUE o aluno aprende (currículo)
Público: Professor sala comum
Seções: 14 (7 disciplinas + BNCC)

Prompts com objetivos SMART e códigos BNCC reais
Critérios observáveis de avaliação exigidos
Legislação referenciada (Lei 13.146/2015, PNEEPEI)
Seção "Recursos e Acessibilidade" duplica intenção do PAEE
14 seções podem cortar em PDFs sem paginação inteligente
PAEE

Plano de Atendimento Especializado

Foco: COMO o aluno acessa (acessibilidade)
Público: Professor AEE / Sala de Recursos
Seções: 6 (barreiras + TA + ambiente)

Diferenciação explícita: PAEE = COMO acessa; PEI = O QUE aprende
Tecnologia assistiva concreta exigida (não "será definido")
Cada adaptação: recurso + barreira + responsável
"Orientações à Família" duplica seção do PDI
Sem articulação explícita com professor da sala comum
PDI

Plano de Desenvolvimento Individual

Foco: Integração global longitudinal
Público: Equipe multidisciplinar + família
Seções: 6 (baseline → meta → indicador)

Análise longitudinal com padrões de progresso/regressão
Cada meta: baseline → período → indicador observável
Família como fator de suporte OU risco (não apenas parceiro)
Risco de gerar cópia do PEI+PAEE sem análise integradora real
Seção "Histórico" pode ficar vazia para alunos novos sem timeline

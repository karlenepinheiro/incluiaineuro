5Roteiro de validação pronto para execução autorizada

Atenção: o passo 0 (deploy) já coloca o código da Etapa 4 servindo tráfego real de produção — não é um "ambiente de teste" isolado, é o próprio sistema live. Recomendo executar em horário de baixo uso e com alguém acompanhando o Supabase Studio (aba Logs/Table Editor) durante os primeiros minutos.

Passo 0 — Deploy (só quando autorizado)

supabase functions deploy ai-gateway --project-ref hvjczfncppaodebopbvd

Não requer AI_ROUTER_MODE nem nenhum novo secret — o default já é 'gemini'.

Opção A (recomendada) — via app real, logado como conta de teste/interna

  1. Fazer login no app com uma conta de teste/interna (não cliente real), com saldo de créditos.
  2. TEXT / ACTIVITY_GENERAL: gerar uma Atividade Geral no IncluiLAB (modo "A4 Econômica") sem anexar aluno → confirmar atividade gerada, quantidade respeitada, SEM Guia do Professor.
  3. ASSESSMENT: gerar uma Avaliação → confirmar Folha + Gabarito, SEM Guia do Professor automático.
  4. ACTIVITY_ADAPTED / WITH_STUDENT: usar o modo "Adaptar" com um aluno de teste selecionado → confirmar atividade adaptada + Guia do Professor, e que o contexto do aluno foi usado.
  5. WITHOUT_STUDENT: repetir uma geração sem selecionar aluno → confirmar que funciona normalmente.
  6. IMAGE: usar "A4 Visual" ou "Premium Ilustrada" → confirmar imagem válida renderizada (isso ainda é Vertex Imagen, apesar do rótulo dizer "OpenAI" na UI — comportamento já mapeado na auditoria original).
  7. JSON: gerar um Estudo de Caso, PEI ou PAEE para um aluno de teste → confirmar documento estruturado válido.
  8. CREDITS_SUCCESS: anotar o saldo de créditos antes e depois de uma geração bem-sucedida → confirmar débito correto e nenhuma reserva pendente (Supabase Studio → tabela credits_wallet/credits_ledger, somente leitura).
  9. AUDIT: no Supabase Studio (Table Editor, somente leitura), conferir que cada geração acima criou uma linha em ai_requests com status='success' e uma linha correspondente em ai_outputs.
  10. AUTH_TENANT / GATEWAY_CONTRACT: confirmar, pela aba Network do navegador, que a resposta de ai-gateway tem exatamente os campos já esperados (result, creditsRemaining, auditId, etc.) e que nenhuma chamada retornou 401/403 inesperado.

Opção B (técnica, complementar) — curl direto, para isolar TEXT/JSON/IMAGE e o teste de falha controlada

Obter um access_token real: logar no app com a conta de teste, abrir DevTools → Application/Storage → Local Storage → chave sb-hvjczfncppaodebopbvd-auth-token → copiar o campo access_token. apikey é a anon key pública do projeto (já presente no bundle do frontend, não é segredo).

De código: inalterado desde o checkpoint da Etapa 4 — reverter index.ts, apagar _geminiProvider.ts, deixar _router.ts/_types.ts desconectados. _vertex.ts/_audit.ts/_credits.ts nunca foram tocados.

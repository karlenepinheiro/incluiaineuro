Seção 3
Causas Raiz por Problema
Crítico Problema 1 — Imagens com qualidade ruim

Causa raiz confirmada: Vertex AI Imagen 4.0 está sendo usado para gerar documentos estruturados com texto, linhas, campos e formulários, mas este modelo é treinado para imagens fotográficas e artísticas, não para layout tipográfico.

O prompt base de imagem (A4_WORKSHEET_STYLE_PROMPT, linha 385 de IncluiLabView.tsx) pede ao Imagen:

'Gerar imagem A4 vertical de atividade escolar brasileira, fundo branco, estilo worksheet didatico premium, titulo grande no topo, cabecalho Nome/Data/Turma, questoes em quadros separados, bordas finas, poucas cores, texto legivel, linhas para resposta...'

Resultado na prática: texto em português ilegível ou truncado pelo modelo, linhas de resposta tortas, quadros irregulares, numeração duplicada ou inconsistente. A aparência é de "ilustração estilizada de worksheet", não de documento escolar real.

Agravante: o descricao_folha enviado como contexto tem limite de 220 palavras — insuficiente para especificar o conteúdo preciso de cada questão. O modelo recebe instruções vagas e interpreta livremente.

Crítico Problema 2 — Imagem não aparece onde deveria

Caminho A (visual/premium): quando o Vertex AI falha (timeout de 25s ou erro 403/400), o callAIGateway lança exceção, o frontend executa atomicReleaseReservedCredits e exibe errorMsg. Não há fallback visual — o professor vê tela de erro em vez da atividade.

Caminho B — código morto: a função generateSmallImagesForAssets (linha 236) que gera imagens individuais por asset e poderia ser o fallback existe no código, mas nunca é chamada por nenhum dos 6 modos de geração atuais. É um resquício de arquitetura anterior.

Caminho C (econômica sem imagem): o modo econômica renderiza ActivityA4Premium(contentJson) corretamente — sem imagem IA. Funciona, mas a ausência de qualquer elemento visual torna a atividade visualmente pobre.

Crítico Problema 3 — Guia do professor enorme

Causa raiz confirmada: buildGuiaEConteudoPrompt (linha 714) solicita ao Gemini um campo guia_pedagogico que é uma string markdown pré-estruturada com 9 seções obrigatórias, definidas no template do prompt:

// Estrutura obrigatória injetada no prompt: ## Objetivo da Aula ← 1 parágrafo ## Metodologia Adaptada ← 1 parágrafo ## Tempo Estimado ← linha ## Materiais Necessários← lista ## Dicas de Mediação ← lista ## Critérios de Avaliação← lista ## Adaptações Inclusivas← lista ## Alinhamento BNCC ← 6 subcampos (componente, ano, código, habilidade, objetivo, adaptação) ## Observações para o Professor ← 1 parágrafo

O Gemini preenche todas as seções fielmente. O resultado (600–900 palavras) é renderizado sem truncamento, colapso ou paginação. Ao exportar o PDF com a aba "Guia do Professor" ativa, esse conteúdo vai integralmente para o PDF via html2canvas — potencialmente 2–3 páginas extras.

Crítico Problema 4 — Atividades premium visualmente estranhas

4a — Visual vs Premium: diferença real é apenas "1 página vs 2 páginas". Em buildOpenAIActivityImagePrompt (linha 781), o único diferencial entre os dois modos é:

const maxPages = mode === 'premium' ? '2 páginas' : '1 página'; // → inserido no prompt: "Máximo ${maxPages}" // Mesmo modelo Vertex AI Imagen 4.0, mesmo endpoint, sem instrução extra de qualidade

4b — Econômica e premium usam o mesmo prompt Gemini. generateA4Economica chama buildPremiumActivityPrompt — o mesmo builder que o modo premium usa conceitualmente. O conteúdo pedagógico gerado pelo Gemini é idêntico para ambos; a diferença está apenas no canal de saída (HTML vs imagem).

4c — Sem especialização por tipo de atividade. O mesmo prompt genérico é usado para caça-palavras, interpretação de texto, matemática, colorir, sequência lógica e associação. Não há templates distintos por tipo pedagógico.

4d — Sem validação pedagógica pós-geração. Não existe verificação de adequação ao ano/série, plausibilidade das opções de múltipla escolha, ou nível de complexidade em relação ao perfil do aluno.

Médio Problema 5 — Exportação/diagramação ruim e divergência preview–export

Para modos Visual/Premium, o PDF usa o caminho de imagem única: a imagem do Vertex AI (dimensões nativas, geralmente ~1024×1024px ou ~1024×768px) é centralizada e escalada numa página A4 (210mm×297mm). Se a Imagen não gerar uma imagem com proporção 210:297 (o que é quase sempre o caso), a folha fica com barras brancas laterais ou o conteúdo parece comprimido.

Para modo econômica, o html2canvas usa scale=2 — pode produzir artefatos em fontes pequenas. O waitForImages usa Promise.all: se qualquer imagem falhar ao carregar, a exportação inteira falha com erro bloqueante.

O guia do professor e a folha do aluno usam o mesmo botão "Baixar PDF" — a aba ativa no momento do clique determina o que vai para o PDF. Se o professor não perceber em qual aba está, pode exportar o guia sem querer, ou vice-versa.

Médio Problema 6 — Persistência e histórico comprometidos

Para modos visual/premium, o content salvo no banco é um IncluiLabActivityContent quase vazio (apenas descricao_folha num info_box), não a atividade real. Ao reabrir da biblioteca, o conteúdo exibido não representa a atividade original.

O imageUrl armazenado é o base64 completo da imagem Vertex AI — podendo ter 500KB–2MB como string. Esse valor vai direto para o banco PostgreSQL sem compressão, redimensionamento ou upload para Supabase Storage. Isso representa risco de timeout de request, tamanho de payload e custo de armazenamento.

Riscos
Risco Gravidade Descrição
Vertex Imagen para estrutura de documentos 🔴 ALTO Modelo inadequado para a tarefa principal. Resultados imprevisíveis com texto ilegível, numeração incorreta e layout distorcido. Não tem solução de prompt — é limitação do modelo.
Base64 no banco crescendo indefinidamente 🔴 ALTO Atividades com imagem podem atingir 2MB por registro. Com uso intenso, custos de armazenamento, timeouts de leitura da biblioteca e degradação de performance são inevitáveis.
Imagem falha → preview vazio (visual/premium) 🔴 ALTO Professor paga 8–15 créditos e recebe erro ou conteúdo praticamente vazio quando o Vertex AI falha. Nenhum fallback útil existe atualmente.
Cobrança sem entrega (modos econômicos) 🟡 MÉDIO Créditos debitados antes de confirmar que UI exibiu o resultado. Falhas silenciosas consomem créditos sem entrega de valor.
Custo Premium ≠ qualidade Premium 🟡 MÉDIO Diferença real entre Visual (8 cr) e Premium (15 cr) é apenas "1 página vs 2 páginas" no prompt. Pode gerar insatisfação e solicitações de reembolso.
Código morto inflando bundle e confundindo devs 🟡 MÉDIO 4 artefatos mortos: buildActivitySchemaPrompt, buildAdaptActivitySchemaPrompt, generateSmallImagesForAssets, ImageGenerationService não chamado. Próximas correções podem ativar código morto por engano.
Exportação falha por imagem única quebrada 🟡 MÉDIO O Promise.all no waitForImages não tem fallback por imagem. CORS, URL expirada ou timeout de uma imagem quebra toda a exportação.

  • Quando imageUrl é null ou falha, renderizar ActivityA4Premium(contentJson) em vez de erro vazio

  • Mover base64 da imagem para Supabase Storage antes de salvar — retorna URL pública permanente
  • Mostrar notificação explícita quando imagem falha, com botão "Tentar gerar imagem novamente"

  • Criar prompt de imagem específico para ilustrações (sem texto, sem layout, apenas elemento visual isolado)
Sprint LAB-3 Guia do professor enxuto e colapsável

  • No export: guia sempre em página separada, nunca misturado com folha do aluno
  • Adicionar botão explícito "Exportar Folha do Aluno" e "Exportar Guia do Professor" separados
Sprint LAB-4 Preview e export A4 fiel

  • Separar previewRef (com sombra/scroll) do exportRef (DOM invisível, fundo branco, sem bordas decorativas)
  • Aumentar scale do html2canvas para 3x no modo econômica (paridade com exportação PNG)
  • Substituir Promise.all por Promise.allSettled no waitForImages — imagem quebrada usa fallback emoji sem bloquear exportação
  • Forçar proporção da imagem Vertex AI ao embutir no PDF: crop/letterbox para 210×297mm
Sprint LAB-5 Histórico e persistência robusta

  • Ao reabrir da biblioteca, recarregar imagem do Storage (não do base64 inline)

Seção 7
Menor Primeira Correção Segura

✅ Patch: popular contentJson para modos visual/premium (Bug B4)

Em IncluiLabView.tsx linhas 2275–2284 (em generateA4Visual) e linhas correspondentes em generateA4Premium, o contentJson é construído com uma seção vazia:

// ATUAL — contentJson quase vazio: const contentJson = normalizeIncluiLabActivity({ title: parsed.titulo_atividade || topic.slice(0, 60), sections: [{ type: 'info_box', title: 'Descricao da folha', content: parsed.descricao_folha }], // ↑ praticamente vazio — só uma caixa de texto com a descrição }, { title: topic });

A correção é usar o parsed.guia_pedagogico + parsed.descricao_folha para construir seções mais ricas no contentJson, derivando objetivos, instruções e questões do guia. Assim, se imageUrl está presente, o comportamento é idêntico ao atual. Se imageUrl é null ou falha, o professor vê uma versão HTML da atividade em vez de conteúdo quase vazio.

Por que é seguro: não altera prompts, não altera créditos, não altera banco, não altera Edge Function, não altera outros módulos. Só melhora o fallback no estado GeneratedResult local do componente.

Seção 8
O Que Não Tocar Agora
⛔ Não trocar o modelo de imagem sem antes definir se a abordagem correta é render HTML → imagem ou continuar com geração direta via IA
⛔ Não mexer em validateActivitySchema ou validateAndRepair — são compartilhados com PEI, PAEE, PDI e outros módulos críticos
⛔ Não remover A4ActivityRenderer ainda — pode ser usado para atividades antigas da biblioteca com formato ActivitySchema
⛔ Não alterar a Edge Function ai-gateway — toda alteração afeta documentos formais, relatórios e checklists além do IncluiLAB
⛔ Não limpar o código morto antes de confirmar que nenhuma entrada da biblioteca depende do fluxo antigo (ActivitySchema format)
⛔ Não aumentar o custo do A4 Econômica para "forçar qualidade" — o problema é arquitetural (modelo errado), não de custo de créditos
⛔ Não misturar correção de guia e correção de imagem na mesma PR — são riscos independentes e o rollback precisa ser granular
⛔ Não mexer em PDFGenerator dos documentos formais, CEO, Kiwify ou prompts globais — fora do escopo desta auditoria
